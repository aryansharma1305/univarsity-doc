# Mentor UI refinement — 14–15 November 2026

> **Update (PR #41, 17 November 2026):** `/` is the animated hero homepage again (headline, crest, single "Activate your account" action; subtitle and badge row stay removed). The four verification forms remain on their own routes, and `/verify` redirects to `/verify/admission-letter`.

This report records the frontend-only state in PR #39. The combined runtime behavior and release gates are documented in [the integration handoff](docs/development/mentor-public-verification-integration.md).

Implemented locally on `feature/mentor-verification-ui`, rebased onto main `18468504aa213589606cee7a16187c8ea12d30f8` after PR #38 (original frontend validation base: `0942978`). Changes are isolated on this frontend branch; no deployment or live database change is included.

Before: large homepage hero, CTA badge row, text-heavy student sign-in visual, and four verification routes with generic unavailable screens. After: a compact titled input and Verify button with a result card on all four routes and the homepage; five-option navigation; student sign-in showing “Welcome to Verification Portal” above the centered, overlapping animated crest.

All four public verification pages still use placeholder states: admission letter, certificate, registration and results. Their existing public API handlers return `UNAVAILABLE`, without looking up a record. The new form therefore keeps entered references local and shows “Coming in a later phase”; submitting never fabricates a verification result or sends an identifier to an unavailable service. There is no approved public success/disclosure contract to populate a student result card yet.

The existing authentication forms, routes, APIs, payment integration and protected records were not changed. A frontend-only motion fix allows the existing crest animation to respond when reduced-motion preferences change.
