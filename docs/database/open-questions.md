# Unresolved client decisions (schema impact)

None of these is guessed in the schema. Each row says how the schema stays open, and what will change once
the client answers.

| #   | Question                                                                                                                                                            | How the schema accommodates it today                                                                                                                                                             | Likely change once answered                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 1   | **Exact grading rules** (grade bands, grade points, pass rules per component, absent/backlog handling, rounding, SGPA/CGPA formulas, which attempts count for CGPA) | `grading_schemes.rules` is free-form JSON, versioned and frozen once ACTIVE; results store `grading_scheme_id` + `calculation_snapshot`. The only seeded scheme is an explicit empty placeholder | A JSON schema for `rules` in `@docversity/validation`; no table change expected                                |
| 2   | **Second public result lookup identifier** (with registration number)                                                                                               | Nothing is hard-coded. `students.date_of_birth` is optional and is not used for lookup                                                                                                           | Possibly a new column (e.g. a roll/reference number or an issued access code) and an index for the chosen pair |
| 3   | **Actual Excel layouts** (wide vs long result sheets, header names, date formats)                                                                                   | `import_jobs.mapping` and `import_rows.raw_data/normalized_data` are JSON; `result_items.source_data` keeps original cells                                                                       | Probably none; possibly `import_jobs.examination_id` for result imports (Phase 8)                              |
| 4   | **Are grades calculated by Docversity or imported as final?**                                                                                                       | `result_items` stores marks _and_ grade/grade point/credits; results store SGPA/CGPA/outcome. Both modes fit                                                                                     | None                                                                                                           |
| 5   | **Certificate numbering format** (pattern, per program/type/year, gap-free?)                                                                                        | `number_sequences` (key, prefix, padding, yearly reset); numbers stored as free `VARCHAR(64)`; allocation is not implemented                                                                     | Sequence keys and the pattern definition (likely in template config)                                           |
| 6   | **Exact course hierarchy** (faculty → department → program → specialisation?)                                                                                       | `programs.department_id` is optional; `programs.level` is free text; registration has an optional department                                                                                     | Possibly a faculty table or a specialisation field                                                             |
| 7   | **Official document templates** (layouts, wording, fonts, seals, signatories, per-program variants)                                                                 | `certificate_templates` (versioned, markup/styles/background nullable) + `program_document_templates` (default + dated overrides)                                                                | Possibly a template `configuration` JSON column (signatories, wording)                                         |
| 8   | **Public field visibility** (what verification pages may show: marks, photo, DOB, parents' names)                                                                   | Visibility is an application concern; `verification_logs` stores hashes, not lookup values                                                                                                       | None expected                                                                                                  |
| 9   | **Legacy WordPress reconciliation** (two legacy certificate tables, legacy number formats, legacy QR token URLs)                                                    | `legacy_mappings` maps any legacy identifier to its new record; certificates are the single target                                                                                               | Migration scripts only; possibly extra `legacy_mappings.source_entity` values                                  |
| 10  | **Registration number normalisation** (is case significant? are internal spaces/slashes significant?)                                                               | Uniqueness uses `upper(registration_number)` only (trimmed, case-insensitive)                                                                                                                    | Stricter normalisation would be a reviewed migration of `registration_number_normalized`                       |
| 11  | **How many certificates of one type a registration may hold** (e.g. duplicate transcript copies)                                                                    | Not constrained; reissues use supersession                                                                                                                                                       | Possibly a partial unique "one ISSUED provisional per registration"                                            |
| 12  | **Curriculum version per student** (which regulation a registration follows)                                                                                        | Results reference exact `program_subjects` rows (which carry `curriculum_version`)                                                                                                               | Possibly `student_registrations.curriculum_version`                                                            |
