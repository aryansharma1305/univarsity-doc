# Roadmap (revised 2026-10-08)

| Phase | Scope                                                                                                                                                                                                                                                               | Status                 |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1     | Monorepo foundation, infrastructure, health                                                                                                                                                                                                                         | ✅                     |
| 2     | Core academic domain schema                                                                                                                                                                                                                                         | ✅                     |
| 3     | Staff authentication, RBAC, CSRF, audit                                                                                                                                                                                                                             | ✅                     |
| 4     | Design system, shells, academic masters, students & registrations                                                                                                                                                                                                   | ✅                     |
| 5     | Student / registration Excel import (incl. the "Registration 2025" layout)                                                                                                                                                                                          | ✅ (awaiting approval) |
| **6** | **Student accounts & activation** — `student_accounts`, single-use activation codes (issue single/bulk, printable), separate student auth boundary, `/student/register`, `/student/login`, `/student` dashboard (own registrations only), `/admin/student-accounts` | Recommended next       |
| 7     | Student profile change requests — DOB, photo (private upload), corrections; admin review queue; apply-on-approval with audit                                                                                                                                        | ⏳                     |
| 8     | Curriculum & examinations — subjects, program curriculum, grading schemes, examinations                                                                                                                                                                             | ⏳                     |
| 9     | Results — entry, result import (reuses the import subsystem), review/publication; portal shows PUBLISHED results; marksheet download                                                                                                                                | ⏳                     |
| 10    | Historic certificates — upload, matching, duplicate detection, authorised review, legacy QR mapping, student document library                                                                                                                                       | ⏳                     |
| 11    | Certificate generation — templates, PDF (Playwright), QR, maker–checker issue/revoke                                                                                                                                                                                | ⏳                     |
| 12    | Public verification portal (registration, result, certificate, QR)                                                                                                                                                                                                  | ⏳                     |
| 13    | Legacy WordPress data migration (with explicit authorisation)                                                                                                                                                                                                       | ⏳                     |

Why accounts before results: imported students already exist and the university needs their DOB and
photo; activation codes can be issued as soon as registrations are imported, and every later portal
feature (results, documents) builds on the student authentication boundary. Phases 8–9 can run in
parallel with 6–7 if two streams are wanted.
